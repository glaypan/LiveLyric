## 一、启动

**推荐方式：双击 `启动 LiveLyric.bat`**

它会启动本地服务（127.0.0.1:17321）并自动打开浏览器。这个服务只做两件事：托管页面、代理歌词接口。页面与接口同源，所以在线取词不需要填任何地址。

> 端口特意用 17321 而不是 3000：3000 是 Node / Vite / Next 这些开发服务的默认端口，同开另一个项目就会撞，撞了以后页面还能打开、取词却一直失败。要换端口用 `node LiveLyricServer.js --port 端口`，或设环境变量 `PORT`。

首次使用需要 Node.js（https://nodejs.org/ ，装 LTS 版即可，无需 npm 安装任何依赖）。

也可以直接双击 `LiveLyric.html` 用，功能一样，只是在线取词需要在弹窗里另填代理地址。

### 主界面

1. 打开后即**控制台**。
2. 点顶栏「输出窗口」弹出独立窗口。
3. 把输出窗口拖到扩展显示器 / 投影仪，按 `F11` 或点顶栏「全屏」。
4. 控制台的任何改动（歌词、样式、字号、背景、播放位置）会实时同步到输出层。

两个窗口通过 `BroadcastChannel` 双向通信，并以 localStorage 分键兜底，不需要额外服务。

> 用 file:// 打开和用 http://127.0.0.1:17321 打开属于两个不同的源，两套窗口不能混用。固定用一种方式打开。

## 二、时间码驱动

时间模型：**歌曲秒 = 时间码秒 − anchor + offset**

- `anchor` 默认 `3600`，即 `01:00:00:00` 对应歌曲 0 秒（演出惯例：0 小时留给 preroll）。
- `offset` 用于整体微调（正数让歌词提前）。
- 外部时间码到达时，用「预测 + 比例追赶」平滑（系数 0.08）；偏差超过 0.5 秒直接硬切。
- 超过 1.2 秒收不到时间码判为失锁，但保留 freewheel 惯性，不会突然卡死。

### LTC（线性时间码，音频线路输入）

1. 左栏「时间码源」选 **LTC**。
2. 选输入设备（声卡 / 调音台 / QLab 输出的音频接口）。
3. 点「开始监听」，允许麦克风权限。
4. `ltcLevel` 电平条要有明显起伏，`ltcLock` 变绿即锁定。

解码方式：跨零间隔判位 + bit cell 相位跟踪，每帧 80 bit，同步字 `0011111111111101`，按位域还原 时/分/秒/帧。不依赖任何第三方库。

> **注意：LTC 是满幅音频信号，电平很高。务必把该通道送到声卡的输入而不是扬声器，否则会损伤听力。**

### 时间码发生器（v1.4.0）

左栏「时间码发生器」可以直接生成一段 LTC WAV，用于对码、喂给调音台 / 录像机、或反过来验证本程序的解码链路。

- **起始码**：`HH:MM:SS:FF`，默认 `01:00:00:00`。
- **时长**：10–600 秒。
- **输出电平**：5%–100%（按满幅比例缩放）。
- **帧率**：跟随左栏当前选择的 24 / 25 / 30fps，不做下拉，避免两边不一致。

「生成并下载」拉取 `/ltc` 并落盘为 `ltc_<fps>fps_<日期>.wav`；「复制链接」把同一地址拷走，可粘到 QLab、OBS 或自写脚本里当资源用。

编码约定（与解码器同一套）：每帧 80 bit，同步字 `0011111111111101`，每 bit 占 2 个 cell，cell = `sr / (fps × 160)`；bit 边界必翻转，`bit=1` 在中点再翻一次。位域为 帧个位(0-3) / 帧十位(8-9) / 秒个位(16-19) / 秒十位(24-26) / 分个位(32-35) / 分十位(40-42) / 时个位(48-51) / 时十位(56-57)。

> 这段音频同样**不能往扬声器送**。它是校验与对码用的信号，不是给人听的。

### MTC（MIDI 时间码）

1. 时间码源选 **MTC**，点「连接 MIDI」。
2. 浏览器弹出 MIDI 授权，允许后选择端口。
3. 支持 quarter-frame（0xF1）与 full-frame（0xF0 7F 01 01 ...）两种报文。

### WebSocket 桥

适用于灯光台、播控软件、自写脚本等无法直接给音频/MIDI 的场合。

时间码源选 **WS**，填地址（默认 `ws://127.0.0.1:8080`），点「连接」。服务端推送 JSON 文本即可：

```json
{"tc": "01:00:12:08"}
{"tc": 3720.32}
{"song": 120.5}
{"cmd": "go"}
{"cmd": "next"}
{"cmd": "prev"}
{"cmd": "clear"}
```

`tc` 为时间码，`song` 直接给歌曲秒（跳过 anchor 换算）。

**断线与重连（v1.3.0）**

- 连接地址填完点「连接」后会记住，刷新页面自动重连，不用每次手填。
- 掉线后按 `1s × 1.8^n` 退避重连，上限 10 秒，界面上状态显示「重连中」。
- 每 5 秒发一次 `{"ping":1}` 心跳；对方回 `{"pong":1}` 即可。心跳与应答都不会被当成时间码。
- 超过 30 秒没有任何数据只标记为「无数据」，**不主动断开** —— 有些发送端只在时间变化时才推帧。
- 断线或静默超时会立刻判失锁，输出层状态转红（见第五章）。

### QLab 配置要点

- QLab 5 的 cue list 里打开 **Timecode** 面板，启用时间码。
- 输出 LTC：添加 **Timecode Cue**，类型选 LTC，必须指定 **Audio Patch**，且输出通道不能为 0。
- 输出 MTC：类型选 MTC，走 **MIDI Patch**。
- **两端帧率必须一致**（本系统默认 25fps，可在左栏切换 24 / 25 / 30）。
- 节目起点惯例 `01:00:00:00`，0 小时做 preroll，与本系统默认 anchor 一致。

## 三、歌词导入

| 方式 | 说明 |
|---|---|
| 拖入 / 选文件 | 支持 `.lrc` `.txt` `.srt` `.ttml` `.xml` |
| 粘贴文本 | 点「粘贴」，直接贴 LRC 或纯文本 |
| 示例 | 点「载入示例」内置 10 行演示歌词，含逐字时间轴 |

解析能力：

- LRC 行级时间轴 `[mm:ss.xx]`
- LRC 逐字标签 `<00:08.20>`（网易云 / QQ 音乐导出的卡拉 OK 格式）
- TTML / Apple Music 风格逐字（`begin` / `end`）
- SRT 字幕块
- 纯文本（无时间轴，仅按行均分）
- **`⌚时:分:秒:帧` 页标记歌词库**（v1.4.0，见下节）

### 带时间码的外部歌词库（v1.4.0）

有人的歌词库是「纯文本 + `⌚` 行交错」的形态：`⌚00:00:04:00` 这样的行标出一「页」该出现的时间码，下面跟这一页要显示的词。这类文件直接导入即可（「导入歌词」选文件，或「粘贴」粘贴原文）。

- `⌚` 行按 `时:分:秒:帧` 解析，帧率取左栏当前选择。
- 一行 `⌚` 后跟单行词（绝大多数情况）→ 该词精确落在这一帧。
- 一页含多行 → 按页内顺序均分到下一页起点之前的时长，不会挤在一起，也不会和下一页重叠。
- `{ }` 分组标记行自动跳过，不参与显示。
- 同一句话在曲子里出现多次时，每处都按自己的码独立成行，互不合并。

整份工程 JSON（含 `songs` 数组、`currentId`）也能直接导入：自动取 `currentId` 对应那首，没有就用第一首；曲名 `title` 会优先于文件名，避免标题变成「XX-歌词库」。


### 网易云 / QQ 音乐在线取词

点中栏「在线」按钮，弹窗顶部会显示内置服务状态：

- **已连接 · 内置服务** → 直接用，不用填地址。
- **未运行** → 没启动服务，双击 `启动 LiveLyric.bat`。

输入框里填**歌名最快**（如 `晴天`），也可以贴分享链接或歌曲 ID：

- 网易云链接 `https://music.163.com/#/song?id=186016` → 自动取 `186016`
- QQ 链接 `https://y.qq.com/n/ryqq/songDetail/0039MnYb0qxYhV` → 自动取该 songmid
- 纯数字 → 当网易云 ID

选「QQ音乐」拿到的通常带**逐字时间轴**（官方 QRC 转 LRC），切到「卡拉OK」样式就能看到逐字填充；「网易云」多数只有行级时间轴，部分歌曲返回 KTV 逐字。

**为什么需要这个本地服务**：浏览器不允许网页直连网易云 / QQ 的歌词接口（跨域 + 防盗链，接口要求特定 Referer）。服务端补上请求头和 CORS 头，页面就能拿到数据。代理地址与端口在 `LiveLyricServer.js` 里，默认 **17321**。

如果想用别的代理，在弹窗「自定义接口」里填模板即可，`{kw}` / `{id}` 会被替换。

### 离线缓存（v1.3.0）

取词成功后会连同完整 LRC 文本一起存进浏览器本地（`livelyric.cache.v1`），上限 24 首，按最近使用淘汰。

- 本地服务没启动 → 直接回退到缓存，提示「已用离线缓存（歌名）」。
- 联网请求失败 → 提示「联网失败（原因），已用离线缓存」。
- 标题会标「（缓存）」，方便区分是不是实时取的。

缓存跟着浏览器和访问地址走。用 `http://127.0.0.1:17321` 和用 `file://` 打开是两套缓存，固定用一种方式打开。换端口等于换源，旧端口的存档与缓存不会自动带过来——换之前先在控制台「导出工程」，新端口「导入」即可。

### 服务接口（自写脚本也可调用）

```
GET http://127.0.0.1:17321/health
GET http://127.0.0.1:17321/lyric?kw=歌名&src=qq|netease
GET http://127.0.0.1:17321/lyric?id=歌曲ID&src=qq|netease
GET http://127.0.0.1:17321/ltc?start=HH:MM:SS:FF&dur=秒&fps=24|25|30&sr=48000&lvl=0..1
```

`/ltc` 直接返回 `audio/wav` 附件（16bit 单声道），`dur` 上限 600 秒，`fps` 只接受 24 / 25 / 30，非法参数返回 400。参数含义与「时间码发生器」卡片一致。

返回：

```json
{"ok":1,"src":"qq","title":"晴天","word":true,"lrc":"[00:00.00]<00:00.00>晴<00:00.16>天..."}
```

## 四、歌词驱动与多首

歌词怎么决定「现在显示哪一行」，有三种模式，在左栏「对齐与偏移」卡片底部切换：

| 模式 | 依据 | 用在什么时候 |
|---|---|---|
| 时间轴 | 歌词自带的 `[00:12.34]` 行时间 | 默认。歌词时间准确时 |
| 时间码 | 忽略歌词时间，把时间码均摊到整首行数 | 歌词没有任何时间轴（纯文本）时 |
| Cue | 每行绑一个绝对时间码 | 时间轴不可信，或演出需要逐句卡点 |

**Cue 模式怎么用**：把时间码走到某一句该出现的位置，点「打点到当前行」，这一行就绑定这一刻的时间码。绑够需要的句子后切到 Cue 模式，播放完全按你绑的 cue 走，不再看歌词原时间轴。每行只存一个 cue，重复打点会覆盖。

**歌单（多首）**：点「歌单 · 多首」，把当前歌词加入歌单，填一个入点时间码（留空则自动接在上一首结束之后）。加满一整场后，外部时间码进入哪一首的区间就自动切到哪一首，用的是歌单里存的歌词快照，切歌不联网。

- 「用当前时间码」把输入框填成此刻的时间码。
- 「定位」把时钟推到该曲入点并立即切过去，用于排练核对。
- 歌单随页面状态保存在本地，关掉再开还在。

只用一首时不建歌单即可，行为与之前完全一致。

### 每首偏移（v1.4.0）

左栏「本首偏移」只作用于当前这一首，单位是秒，正数让这一首整体推后、负数提前。它和「对齐与偏移」里的全局微调**叠加**，互不覆盖：

- 点「应用」：在当前偏移上叠加你填的秒数（可反复微调，例如先 +2.5 再 -1）。
- 点「恢复」：一次性退回这一首最开始的值，不做逐次回退。
- 偏移按曲名存在本地，切歌自动跟随；换回同一首时仍然生效。

用途是**逐首对码**：同一场里各首歌的前奏长度不同，用全局 offset 会顾此失彼，每首记住自己的差更稳。

> 本首偏移作用于外部时间码驱动（LTC / MTC / WS）。内部音频时间轴播放时它不参与，避免播放位置被偏移量带偏。

### 歌单连续累计（v1.4.0）

歌单弹窗顶部「响应方式」两档：

| 档位 | 行为 |
|---|---|
| 独立 | 各首用自己填的入点，互不影响（默认，与 v1.3.0 一致） |
| 连续 | 按列表顺序累计前一首的总时长 + 「每首间隔」，依次推后本首起点 |

连续模式下，列表里的时间码会显示**累计推后之后的实际入点**，前面带 `⇢` 标记；歌词内部的码本身不会被改写。间隔可填 0–30 分钟，用于换场、换乐器、主持人串场这类固定空档。

新增曲目在连续模式下永远排到末尾，不按时间码重排——这是连排的逻辑顺序，不是时间顺序。

**切歌过渡（v1.3.0）**：整首歌词被替换时，输出层不是硬切，而是先压黑再 240ms 线性淡入。基于时间戳而不是动画帧，所以哪怕窗口被切到后台也照常走完。

## 五、显示与样式

- **风格**：经典 / 卡拉 OK / 霓虹 / 弹跳 / 极简 / 竖排（国风）
- **背景**：无 / 渐变呼吸 / 极光 / 星尘 / 声波 / 图片或视频（本地文件）
- **比例**：16:9 / 9:16 / 4:3 / 1:1，切换后字号、行距、安全区自动重算
- **字号**：60–200，**行距**：1.0–2.0
- 当前行 ±1 行窗口化渲染，翻页式推进，不会因总行数漂移
- 逐字填充用 `--p` 进度变量驱动，帧级对齐
- 顶栏 `showTc` 可显示时间码水印，`cap` 控制上下行是否显示

输出层全屏后自动隐藏 HUD，只留歌词与背景。

### 舞台可读性（v1.4.0）

- **字距**：60%–250%。各样式有自己的基准（竖排最宽、极简最紧），你填的倍数乘在基准上，100% 即原样。
- **描边**：0–10px + 颜色。投影幕布、强光、有景深的舞台，描边比阴影可靠。
- **阴影**：0–40px 模糊 + 颜色。
- **镜面**：关闭 / 左右 / 上下，只翻歌词层，HUD 与控制台不动。带反光镜的提词器用「左右」。

> 逐字填充（卡拉 OK 样式）的字符字身是透明的，阴影对它不生效，描边仍然有效。

### 倒计时与临时上屏（v1.4.0）

左栏「现场工具」：

- **倒计时**：填分钟数 → 开始。输出层居中显示 `MM:SS`，最后 10 秒红白闪缩；打开「全屏大字」时歌词暂时让位，只留倒计时。停止即隐藏。
- **临时上屏**：输入一句话 → 上屏，压在歌词上方，歌词照常推进；「清除」立刻撤下。适合「下一首是××」「还有 5 分钟开场」。

两者互不干扰，也不会写进歌词或歌单；倒计时结束自动隐藏。

### 工程导出 / 导入（v1.4.0）

右栏「工程」：

- **导出工程**：把歌词、样式、全部时间码设置、歌单（含每首歌词快照）打成一份 JSON。
- **导入工程**：读回同一份 JSON，恢复全部状态。

导出时会剥掉本机临时的 `blob:` 媒体地址（换机必然失效），其余原样保留。用于换机器、换浏览器、备份彩排版本。

### 失锁告警（v1.3.0）

输出层左下角 HUD 的状态字样会随失锁变红，台上扫一眼就能看见：

| 状态 | 含义 |
|---|---|
| `STANDBY` | 还没开始跑 |
| `RUN · LOCK` | 外部时间码正常，已锁 |
| `RUN · FREE`（红字） | 外部时间码断开或 30 秒无数据，正在按最后的时间自由续走 |
| `RUN` | 内部时钟在跑 |

控制台的时间码大字与顶部状态标签同步反映：`IDLE` / `LOCK` / `FREE`（红字，失锁续走）/ `RUN`，WS 掉线时状态标签会变「重连中」或「无数据」。

外部时间码断开时，**时间码不会停走**，而是按最后一帧的自由续走继续推进，同时把状态标红。这是演出取舍：断码的瞬间宁可让歌词继续往下走、让人看到红字告警，也不要当场黑屏。


### 后台 / 最小化时的续航（v1.3.0）

浏览器会把后台窗口的动画帧（`requestAnimationFrame`）节流到几乎停摆，演出时输出窗口常被别的程序挡在后面。

v1.3.0 的控制台与输出层都加了定时器兜底：动画帧超过 200ms 没回调就由定时器接管，最短每 100ms 推一帧。**窗口被最小化、被遮挡，时间码与投屏画面仍然继续走**。

## 六、投屏方式

- **扩展屏**：系统显示设置里设为「扩展」，把输出窗口拖过去，`F11` 全屏。
- **镜像**：系统设为「复制」，两个屏幕同画面。

## 七、故障排查

| 现象 | 原因与处理 |
|---|---|
| 弹窗显示"内置服务未运行" | 没开 `启动 LiveLyric.bat`；或 17321 端口被占用。换端口用 `node LiveLyricServer.js --port 端口`，页面会自动探测同源地址 |
| 双击 bat 闪退 | 未安装 Node.js；窗口会停顿并提示，按提示装 LTS 版 |
| 取词报"搜索无结果" | 歌名太短或含特殊符号，换全名，或直接贴歌曲 ID |
| 取到的是翻唱 | 网易云搜索结果第一条不一定原版，改用分享链接里的 ID |
| LTC 电平有但锁不上 | 帧率不匹配（QLab 与本系统必须同为 24/25/30）；或电平过高削波，中间加衰减 |
| LTC 电平条不动 | 选错输入设备；或系统未给浏览器麦克风权限 |
| MTC 连不上 | 未授权 MIDI；或端口被其他软件独占 |
| 歌词不跟随时间码 | 检查 anchor 是否为 `01:00:00:00`，offset 是否被误调 |
| 整首歌词整体偏掉几分钟 | offset 被写成超范围值。v1.3.0 起所有写入点都夹紧到 ±3000ms，读存档时也会自动修回；若仍偏，点「重新对齐」或把 offset 归零 |
| 点某行歌词提示「还没收到时间码」 | 外部源下还没收到第一帧，`nowSong()` 恒为 0，此时对齐会把整行时间写进偏移。等时间码进来再点 |
| 输出窗口空白 | 控制台没点「输出窗口」；或浏览器拦截弹窗 |
| 样式同步延迟 | 正常，总线 160ms 轮询兜底，极端情况最多滞后一帧 |
| 控制台与输出不同步 | 两个窗口的源不一致（一个 file://、一个 http://），统一用 bat 打开 |
| 切歌没反应 | 歌单入点必须按时间顺序；先在歌单里点「定位」确认能切过去，再看时间码是否真的越过了入点 |
| Cue 模式不动 | 当前行还没打点。没打过点的行在 Cue 模式下会被跳过，只有已打点的行才会出现 |
| 打点后顺序错乱 | cue 必须随时间单调递增。往回补打点会让后面的 cue 失效，重打一遍即可 |
| WS 状态反复「重连中」 | 地址填错或对方服务没起；先 `curl` 一下地址确认能握手。退避上限 10 秒，不会打爆对方 |
| 状态显示「无数据」但没断开 | 对方 30 秒没推帧。若本来只在变化时推，属正常；想强制断开点「断开」再「连接」 |
| 输出层状态红字 `RUN · FREE` | 时间码断了，正在按最后的码自由续走。恢复连接或检查发送端 |
| 换了地址刷新后又连旧的 | 地址只在点「连接」时保存。填完一定要点一次「连接」 |
| 控制台开着时间久了变卡 | 每帧重写整块状态面板会持续产生 DOM 变更。v1.3.0 起改为「值没变就不写」，实测从 1400 次/秒降到 146 次/秒；想自己对比就在地址后加 `?opt=0` 退回旧行为 |
| 拖偏移滑块时手一松就弹回 | 旧代码每帧写 `input.value` 会抢输入的焦点。v1.3.0 起判断 `document.activeElement`，正在拖的时候不覆写 |

## 八、自检

在地址后加 `?debug=1`，页面会在 1200ms 后把自检结果写进页面标题：

```
SELFTEST {"ltc":{...},"clock":{...},"src":"ws","csrc":"ws","tc":0,"ext":0,"ws":{...},"parse":{...},"setlist":{...}}
```

- `ltc`：合成 6 帧 LTC 波形回灌解码器，正常解出 5 帧连续时间码（最后一帧需下一帧边界结账）。不依赖音频硬件，可确认解码器本身没坏。
- `clock`：把时间码喂进时钟，看歌曲秒与命中行号是否对得上。
- `parse`：当前歌词的总行数、带逐字时间轴的行数、首行字数。
- `setlist`：多首定位与切歌。`inA` / `inB` / `before` / `backA` 是四个时间码落到的曲目索引，`hits` 是切歌回调实际触发的顺序（正常为 `1,0`）；`tl` / `cl` / `cueHit` 是三种模式在同一时刻取到的行号，应互不相同。
- `src` / `csrc`：存档里的时钟源与时钟对象当前实际用的源，两者应一致。
- `tc` / `ext`：当前时间码秒与外部帧戳。外部源有帧时 `ext` 不为 0。
- `run` / `lock`：时钟是否在走、外部码是否锁定。外部源下 `lock=false` 而 `run=true` 就是「失锁续走」，此时控制台 `#srcTag` 显示红色 `FREE`。
- `ws`：`st` 连接状态、`url` 地址、`gen` 连接代次、`rs` 底层 `readyState`、`last` 距上一条消息的毫秒、`err` 解析或喂码异常、`raw` 最后一帧原文。

自检期间会临时屏蔽切歌回调，并保存/恢复时钟源与外部帧戳，不会改动你正在用的歌单、歌词和正在跑的时间码。

## 九、已知边界

- 浏览器直连网易云 / QQ 官方歌词接口会被同源与防盗链拦，必须走本地服务。
- 网易云同时请求新旧两个接口并按行数择优：新版接口精度到毫秒，但匿名态下正文可能被版权过滤成残缺；旧接口百分秒精度、正文完整。
- 网易云的逐字（`yrc`）在匿名请求下基本拿不到字级时间，逐字请用 QQ 源。
- 输出窗口全屏依赖浏览器 `requestFullscreen`，需一次用户手势触发。
- 竖排样式下拉丁字母按 CJK 竖排规则逐字成列，属该排版固有表现。
- 歌词缓存只存本机浏览器，换机器或清缓存后需重新联网取词。
- 面板的「写前比对」假设状态字段只由控制台自己写。已逐个核对；若以后别处也要改同一行文字，得同时清掉缓存，否则会停在旧值。
